# Deliveries latency constraint implementation plan

## Direction

Implement GitHub issue #16 as one database-enforced invariant with no sender or measurement changes.

## Steps

1. Update `design.md` with the nonnegative contract and the valid zero case.
2. Add a focused schema test that fails because the named check constraint is absent.
3. Add the smallest Drizzle table check and run the focused test again.
4. Run `bun run db:generate` so Drizzle owns the SQL migration and metadata snapshot.
5. Inspect the generated diff and migration predicate.
6. Apply the migration to compose PostgreSQL and verify that a negative insert fails while a zero insert succeeds inside a rollback-only validation transaction.
7. Run `bun run check`, `trunk check --all --no-fix`, and `git diff --check`.
8. Review the complete diff against the frozen issue contract, repair verified findings, and rerun affected checks.
9. Create concern-based commits, push the branch, open the pull request, and observe hosted review and CI at the exact head.

## Failure and completion checks

The focused test must first report that the expected delivery check is missing.
The PostgreSQL validation must deliberately attempt the invalid insert and observe the named check constraint in the error before its valid zero case is trusted.
Completion requires the repository gates, hosted Codex code and security reviews, and GitHub CI to pass at the pushed head.
